# IndoGRC Pro - ICOFR Lifecycle Platform

## Project Overview
IndoGRC Pro is a production-grade web application designed to digitize the ICOFR (Internal Control over Financial Reporting) lifecycle for State-Owned Enterprises (BUMN). It is fully aligned with **Regulation SK-5/DKU.MBU/11/2024**, providing a standardized, transparent, and auditable platform for the mandatory 5-step ICOFR process.

**Key Features:**
*   **BPM Visualization:** Visual business process mapping with standardized legends as per **Lampiran 3** (Oval for Start/End, Hexagon for Risk, Inverted Triangle for Archive, Cylinder for System/Data Media).
*   **Risk Library Cluster:** Industry-specific risk repository for **11 BUMN clusters** (Energy, Food, Finance, Mining, etc.) as per **Lampiran 2**.
*   **Scoping & Materiality:** Automated OM/PM calculation with **Group Multipliers**, proportional allocation, and a dedicated **Equity Investee Monitoring** module (**FAQ No. 5**).
*   **Whistleblowing Recap:** Integration of fraud indicators from WBS into ICOFR risk assessment (**Lampiran 1 Principle 14 & 15**).
*   **Change Management Log:** Regulatory documentation of all modifications with a formal **Change Request & Approval Workflow** (Lini 1 to Lini 2) as per **Lampiran 6**.
*   **Regulatory Reporting:** Automated "Asesmen Manajemen" (Appendix 11) with **Digital Sign-off & Lock**, **QR Code Document Verification**, and automatic effectiveness conclusions.
*   **Governance & Integrity:** Built-in **Auditor Cooling-off Validation** (Bab II) and accountability **KPI Dashboards** for cycle tracking.

## Technology Stack

### Frontend
*   **Framework:** React 18+ (Vite)
*   **Language:** TypeScript
*   **State Management:** TanStack Query, Zustand
*   **Diagramming:** React Flow (BPM Visualization)
*   **Styling:** Tailwind CSS, Shadcn/UI, Framer Motion
*   **Forms:** React Hook Form + Zod

### Backend
*   **Runtime:** Cloudflare Workers / Node.js
*   **Framework:** Hono (Lightweight API routing)
*   **Persistence:** PostgreSQL / Cloudflare Durable Objects
*   **ORM:** Drizzle ORM (PostgreSQL dialect)

## Directory Structure

*   `src/pages/`:
    *   `scoping/`: Materiality, Scoping Matrix, and Haircut Wizard.

    *   `audit/`: External Assurance Portal (KAP).
    *   `csa/`: Control Self-Assessment workspace with Line 2 validation.
    *   `testing/`: TOD & TOE testing workbench with 6 pilar evaluation.
    *   `deficiencies/`: Kanban board, DoD Wizard, and Aggregate Analysis.
    *   `reports/`: Regulatory reports, WBS recap, and digital sign-off.
*   `shared/`: `types/` per-domain (`common`, `org`, `scoping`, `rcm-bpm`, `csa-testing`, `deficiency`, `user`) + barrel `types.ts` (Source of Truth), `constants/` (data-blob materialitas dkk), compliance utilities.

    *   **Batasan scope (dashboard/tabel di luar cakupan skill):** skill ini untuk landing page/portfolio, BUKAN dashboard/tabel data. Untuk UI enterprise regulasi (tabel, toolbar filter, kartu KPI), cukup checklist Anti-AI Slop di bawah + mandat `better-interface` (butir 2); aktivasi skill eksplisit penuh dicadangkan untuk surface marketing/landing/empty-state yang butuh arahan desain.

        *   **No decorative italic (judgement call, tetap di sini):** Dilarang menggunakan font miring (`italic`) pada data tabel audit, label regulasi, keterangan status, atau watermark audit. Teks kepatuhan BUMN harus tegas dan objektif.
        *   **Design system tokens (judgement call, tetap di sini):** Gunakan token Shadcn / Tailwind semantik (`--primary`, `--muted`, `--border`, dsb.), dilarang hardcoded warna neon/gradien ungu-pink acak.
        *   **Workbench Locking Tests:** Setiap penambahan komponen workbench baru (Scoping, Testing, Deficiency) WAJIB disertai unit test terdedikasi (`*.test.tsx`) yang menguji rendering dan interaksi kuncinya.

    *   **BPM Edge Invariants & Gesture Integrity:** Seluruh threshold penurunan (`DOWNWARD_PLUNGE_THRESHOLD_DY`, `SAME_LANE_SEQUENTIAL_FLOW_THRESHOLD_DY`), ceiling aman (`SAFE_HEADER_CEILING`), dan elevasi layer (`BPM_CANVAS_Z_INDEX`) WAJIB diimpor dari `src/utils/bpm-constants.ts` (dilarang magic number literal). Handler drag koneksi (`onConnect`) WAJIB memvalidasi titik awal gestur via `normalizeConnectionDirection` (`src/utils/bpm-connection-direction.ts`) agar arah panah tidak pernah terbalik (B -> A). Belokan lateral wajib menyertakan clearance minimum 20px dan dikunci dengan collision test. Detail lengkap: [`docs/agents/bpm-routing.md`](docs/agents/bpm-routing.md).
    *   **BPM Node Handles & Quick-Connect Group Isolation:** Setiap komponen node proses BPM yang membungkus `EightConnectionHandles` WAJIB menyertakan kelas Tailwind `group` pada kontainer induknya. Hal ini memastikan kontrol arah koneksi (Quick-Connect) dan titik handle tersembunyi dengan sempurna saat idle dan hanya muncul secara kontekstual saat pengguna berinteraksi (hover/selected), mencegah kebocoran artefak segitiga hitam atau glyph panah mentah di kanvas.
*   **Repo Guardrails:** Delta/contract gates beyond tsc/eslint/vitest (loc, any-delta incl. non-null assertions, i18n, api-contract, per-barrel route-lock tests, mutation `onError` rule), deployment/cross-boundary verification rules, and their CI wiring. Details: `docs/agents/guardrails.md`.
*   **Responsive Dual-Render Testing:** Komponen yang dual-render card mobile (`block md:hidden`) + tabel desktop (`hidden md:block`) muncul DUA KALI di jsdom karena class `hidden` Tailwind tidak menyembunyikan apa pun di test. Test WAJIB pakai `getAllByText` (mis. `toHaveLength(2)` untuk mengunci kedua view) atau scope query per view, dan WAJIB menegaskan scroll/sticky container via `closest()` bukan `parentElement` agar refactor wrapper responsif tidak mematahkan suite. (Pelajaran 2026-09-30: `RCMStickyHeader` + `CSARealizationTable`.)
*   **Heavy CLI Execution (Windows OOM Guard):** `type-check` / `lint` / `build` / `test` emit output that crashes the PowerShell host when piped — redirect to a file first, then read it back; never run two heavy commands in parallel. Pada lingkungan terbatas, jalankan `type-check` per-target (`npm run type-check:app`, lalu `type-check:worker`) daripada script gabungan. Full protocol: `docs/agents/heavy-cli.md`.
*   **Mandat Inspeksi Visual Multimodal (Anti-Script Waste):** Dilarang keras menulis skrip Python ad-hoc (seperti PIL/matplotlib) untuk memotong, mengukur, atau menganalisis screenshot dan PDF jika model AI dapat melihat media secara multimodal langsung. Setiap masukan visual (gambar tangkapan layar antarmuka, PDF, dsb.) WAJIB diinspeksi secara langsung via kapabilitas visual bawaan model tanpa membuat script eksternal sekali pakai yang mengotori repositori.
*   **Navigasi SPA Internal vs HTML Anchor (Strict Client Routing):** Dilarang keras menggunakan tag HTML mentah `<a href="...">` untuk navigasi rute internal aplikasi. Semua navigasi internal WAJIB menggunakan `<Link to="...">` atau `useNavigate()` dari `react-router-dom` guna mencegah full browser reload yang menghancurkan in-memory cache TanStack Query dan state aplikasi. Aturan ini ditegakkan secara mekanis oleh ESLint (`eslint.config.js`).
*   **Pencarian Kode di Lingkungan Windows (Tool Economy):** Di lingkungan Windows, sistem tidak menyediakan binary GNU `grep`. Agen WAJIB menggunakan `rg` (ripgrep) atau `git grep` untuk melakukan pencarian teks/regex di seluruh repositori secara instan dan efisien.
*   **Ketertelusuran BPM ↔ RCM & Penelusuran Langkah Terindeks:** Pencocokan relasi antara langkah diagram alur (`bpm_diagrams`) dan kontrol risiko (`rcms` / `rcm_controls`) di database wajib mengandalkan foreign key terindeks relasional (`bpm_node_rcms`), DILARANG menggunakan query runtime `LIKE '%...'` yang lambat pada backend. Ekstraksi dan pencocokan nomor referensi langkah (`Ref_Langkah_BPM` ↔ `stepRef`) di sisi client wajib bersumber tunggal pada modul murni `src/components/rcm/editor/utils/step-ref-utils.ts`.
