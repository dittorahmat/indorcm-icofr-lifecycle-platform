## Context

See [proposal.md](proposal.md) for motivation.
Currently, `MaterialitySimulation` in `@shared/types.ts` stores numerical materiality values (`benchmarkValue`, `omPercentage`, `haircutPercentage`, `omValue`, `pmValue`, `isLocked`), but does not store formal justification fields. In the UI, `MaterialityParamsCard.tsx` provides parameters editing and recalculation, while `ScopingEditorHeader.tsx` handles locking/freezing simulations. Scoping locks currently only check basic status rather than qualitative justification completeness.

## Goals / Non-Goals

**Goals:**
- Extend `MaterialitySimulation` to store structured justification data (`MaterialityJustification` interface).
- Provide a clean, accessible dialog (`MaterialityJustificationModal.tsx`) accessible from `MaterialityParamsCard` and the locking flow.
- Support 4 key categorical factors + real-time auto-generated narrative synthesis + supplementary notes (Audit Committee decree / reference doc).
- Enforce mandatory validation in the Lock/Freeze action: if incomplete, prevent locking and open/prompt the justification modal.
- Adhere strictly to the institutional UI standards in `AGENTS.md` (no sub-12px font, enterprise rounded-md/rounded-lg borders, solid background, full i18n support in EN & ID).

**Non-Goals:**
- Complex multi-level approval scoring engine (simple 4-factor audit defense is sufficient for now).
- Forcing justification input in the initial snapshot upload modal (`SetBenchmarkModal`); justification is consolidated in the Scoping Editor where the complete equation (Benchmark + OM + Haircut) is finalized.

## Decisions

### 1. Data Structure in `@shared/types.ts`
We define:
```typescript
export interface MaterialityJustification {
  entityCharacteristics: 'profit_oriented' | 'asset_intensive' | 'revenue_driven' | 'volatile_breakeven';
  internalControlMaturity: 'effective_strong' | 'moderate' | 'deficient_material_weakness';
  auditAdjustmentHistory: 'low_clean' | 'moderate' | 'significant';
  systemStability: 'stable' | 'major_change_erp_restructure';
  autoGeneratedNarrative: string;
  supplementaryNotes?: string;
  justifiedAt?: string;
  justifiedBy?: string;
}
```
And add optional `materialityJustification?: MaterialityJustification;` to `MaterialitySimulation`.
*Rationale*: Strong typing prevents arbitrary schema divergence while leaving space for optional free-text committee notes.

### 2. Auto-Narrative Generation Utility
A pure helper function `generateMaterialityNarrative(factors, simParams, t)` generates localized strings reflecting the chosen benchmark, OM %, PM %, and reasons.
*Rationale*: Auditors appreciate a cohesive executive summary paragraph, but assembling it programmatically ensures consistency and saves user time.

### 3. Locking Guard Workflow
In `ScopingEditorHeader.tsx` (or parent lock handler in `useScopingPage`), when user triggers "Lock / Freeze Scoping", evaluate:
```typescript
const isJustificationComplete = Boolean(
  simulation.materialityJustification?.entityCharacteristics &&
  simulation.materialityJustification?.internalControlMaturity &&
  simulation.materialityJustification?.auditAdjustmentHistory &&
  simulation.materialityJustification?.systemStability
);
```
If false, intercept the action with a descriptive warning toast/dialog and open the `MaterialityJustificationModal`.
*Rationale*: Satisfies the prerequisite rule agreed upon during discovery without blocking users from drafting numbers earlier.

## Risks / Trade-offs

- **[Existing Simulations Lack Justification]** → Mark older existing simulations with a neutral status badge ("Justification Pending" or "Draft Justification") without crashing existing views; require justification only upon next lock/edit.
- **[Modal Clutter]** → Keep the 4 factors as clear card-like radio groups or clean select items, with immediate narrative preview below, ensuring completion takes under 30 seconds.
